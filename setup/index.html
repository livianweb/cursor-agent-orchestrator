Configuración post-clone

Tres capas independientes. Esta página vive en el repo del orquestador; no sustituye la pantalla /settings/git del producto askbox.

0. Clonar e instalar

URL del repositorio del kit (sustituye si usas un fork):

git clone https://github.com/livianweb/cursor-agent-orchestrator.git
cd cursor-agent-orchestrator
./configure

Instalar en tu aplicación — repo nuevo o existente (capa B):

./install.sh /ruta/a/tu-proyecto

Solo copia piezas del orquestador (auto-orchestrator, multitask-ownership, skills plan-implement-verify, askbox-first, git-autopilot). No borra tus *-conventions.mdc, hooks ni otros skills.

  • Sin flags: si un archivo ya existe y difiere → se salta y se avisa.
  • --dry-run: simula sin escribir.
  • --no-template: sin plantilla de convenciones (solo orquestación).
  • --force: backup .bak-… y sobrescribe lo que difiera.
Capa A

Askbox LLM (askbox-first)

Opcional pero recomendado: el agente usa el gateway askbox para UI/copy antes de gastar subagentes Cursor.

  • ASKBOX_API_URL — base de la API, p. ej. http://127.0.0.1:8066
  • ASKBOX_ACCESS_TOKEN — token de proyecto ab_live_… (scope ask:read)

Crear el token en la UI de askbox: /projects → tokens. No commitear ni pegar en git.

# En ~/.bashrc, profile de Cursor, o env del agente:
export ASKBOX_API_URL="http://127.0.0.1:8066"
export ASKBOX_ACCESS_TOKEN="ab_live_…"

Skill: .cursor/skills/askbox-first/SKILL.md

Capa B

Proyecto destino y git de la app

Tras ./install.sh (válido en repos nuevos o con .cursor/ ya poblado). Commits autopilot van al remoto del repo abierto en Cursor, no al del kit.

  1. Tras ./install.sh …, abre el proyecto destino en Cursor (modo Auto).
  2. Opcional: cp .askbox/git-settings.json.example .askbox/git-settings.json en ese proyecto.
  3. gh auth login y git remote add origin … (o gh repo create) en el proyecto.

Skill: git-autopilot · Plantilla pantalla propia: templates/git-settings-screen.md

Capa C

Git del orquestador (este repo)

Cuando mejoras rules/skills del kit, commit y push al remoto de cursor-agent-orchestrator.

./configure --kit-git
gh auth login
git remote -v   # debe apuntar al repo del kit
git push origin master

Si un despliegue askbox monta este repo en EXTRA_REPOS, puedes usar /settings/git?repo=cursor-agent-orchestrator como atajo — sigue siendo git del kit, no “git global”.
