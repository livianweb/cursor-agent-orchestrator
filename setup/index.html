Kit portable · Cursor Auto + Multitask

Configuración post-clone

Ya estás en el repo del orquestador (este wizard en setup/). Aquí configuras el gateway askbox de tu cliente (capa A, opcional) y copias rules/skills a la carpeta de tu aplicación (capa B). La capa C es git y auto-actualización de este kit, no de tu app.

Orden recomendado: Paso 1 Askbox → Paso 2 Instalar en proyecto → Paso 3 Git del kit.

Paso 1 · Askbox Capa A

Askbox LLM (askbox-first)

Opcional: URL y token del gateway askbox del cliente (cada instancia puede ser distinta). El agente los usa para UI y copy antes de gastar subagentes Cursor. Déjalos vacíos si aún no tienes askbox.

Crear el token en la UI de tu instancia: /projects → tokens. No commitear ni pegar en git.


      

      
Skill: .cursor/skills/askbox-first/SKILL.md

      Paso 3 · Auto-update
      Capa C
      
Actualización diaria del kit

      

        En cada máquina con un clone del kit: git pull --ff-only y
        vuelve a ejecutar ./install.sh en los proyectos registrados en
        .askbox/orchestrator-targets (se añaden solos al instalar).
      

      

        
        
Por defecto 06:00 hora local. Desactivar sin borrar cron: ORCHESTRATOR_AUTO_UPDATE=0 en la línea.

        

          
          
          
          
          
        

        

        

      

      
CLI: ./scripts/install-auto-update-cron.sh · Doc: docs/auto-update.md

    


    

      Paso 3 · Git del kit
      Capa C
      
Git del orquestador (este repo)

      
Cuando mejoras rules/skills del kit, commit y push al remoto de cursor-agent-orchestrator.

      

        
./configure --kit-git
gh auth login
git remote -v   # debe apuntar al repo del kit
git push origin master

        
      

      
Remoto y push del kit: gh, git local y opcionalmente
        .askbox/git-settings.json en este repo.
